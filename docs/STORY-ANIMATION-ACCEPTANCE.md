# Three-module teaching animation refresh

Date: 2026-11-12, Asia/Shanghai. Requested scope: make Array, Linked List and Queue easier for children to understand through concrete animated objects, using Stack's stone lesson as the reference. Workspace based on 5ec2a2c with retained uncommitted resilience work. No PPT edits or GitHub push in this iteration.

## Delivered experience

- **Array / Supply Camp:** wooden supply boxes on numbered shelf positions. Insertion first moves later boxes right, then lowers the newcomer into the gap. Removal lifts the chosen box before survivors close the gap. Growth lifts the same supplies into a bigger shelf without inventing new supplies. Read/replace/traverse use a spotlight while place labels remain fixed.
- **Linked List / Misty Forest:** fixed stone beacons, named ropes and a moving HEAD sign. Reference edits redraw the actual next connection, with the old route faded during the change. Safe insertion first prepares the new beacon's successor before reconnecting the previous beacon or changing HEAD. Reading uses a guide light; a detached beacon is explicitly identified as off the HEAD trail. Removed stones can remain visible off the trail; loops are called out rather than hidden.
- **Queue / Harbor Pier:** little sailboats, a wooden pier, FRONT/REAR labels and a departure area. Newcomers join behind waiting boats. Only the front boat sails out; survivors keep their order. Peek lights the front boat without removing it or changing departure history.

Every accepted move has **Before → Watch the move → After**, short plain-language captions and pause/replay controls. Observation playback and actual Python operation replay allow 6.4 seconds per operation at 1×, so the inner three-part animation has time to finish, including at 2×. The single-move phase timer advances at 1.1-second intervals; object transitions take approximately 0.8–0.9 seconds. Speed adjusts the interval between operations. Manual phase buttons remain available.

All three views share these scenes across observation, Python results, independent challenges and teaching activities. Actual Python replay now passes the matching event index into the renderer, so stepping backwards/forwards cannot borrow another operation's narration. Detailed values/references are still available in a collapsed “after this move” result panel, keeping the child-facing scene primary.

The intermediate display is an explanatory preview, not a new structure mutation. Story controls never call task actions, grading, mastery or progress updates. The authoritative operation evidence and final state remain unchanged. Reduced motion defaults to the final view and removes tween durations; Before/Watch/After remain selectable for static comparison. No new image-generation, external asset or network dependency is introduced; scenery and objects are native SVG/CSS using the existing motion library.
