## 一、工程脚手架（Phase 0）提示词

```
基于 Vite + React + TypeScript 搭建「AlgoNavigator 数据结构可视化教学平台」前端脚手架，目录严格按规范创建：src/app、src/components、src/engine、src/tutor、src/content、src/state、src/assets。
配置 ESLint + Prettier + Vitest，新增 .gitignore 忽略 node_modules、dist、构建产物、.env。实现一个可运行的空白 React 入口页，npm run dev 可正常启动，lint 和 vitest 测试命令无报错。不要引入额外 UI 框架，全局样式预留地下遗迹深色主题变量。
```

## 二、Phase 1 栈动画引擎提示词

### 2.1 类型与状态定义

```
在 src/state 下定义 StructureState 类型，实现栈的完整状态模型：栈内元素列表、每个元素的标识、图案类型（base/moon/sun/star/cracked）、栈顶标记状态、动画阶段（idle/pushing/popping/peeking）。所有状态不可变更新，纯函数计算栈的布局坐标，石块宽高比固定 2:1，垂直无缝堆叠，坐标计算逻辑单独抽离纯函数，可被单元测试覆盖，不耦合 React 和动画库。
```

### 2.2 栈渲染器

```
在 src/engine 下实现 StackRenderer，使用 D3 完成数据绑定和布局计算，Framer Motion 处理石块的入场（从上方落下）、退出（向下方消失）、位置过渡；栈顶增加独立 SVG 箭头/标记，指向当前栈顶石块。渲染层只接收 StructureState 输出坐标和贴图资源，不持有业务逻辑。石块贴图从 src/assets 资源索引导入，替换默认占位矩形。
```

### 2.3 动画舞台与控制器

```
实现 AnimationStage 组件，提供播放、暂停、单步前进、速度调节（0.5x/1x/2x/4x）四个控件；控制器状态独立抽离成纯 hook，支持步进队列推进、暂停时冻结帧、速度全局生效。编写手写动画步骤 fixtures，覆盖 push 入栈、pop 出栈、peek 查看栈顶三个基础操作的完整状态序列，无需接入 Python 执行环境即可播放演示动画。舞台左侧预留操作区，右侧预留代码面板位置，背景图为大厅遗迹素材。
```

### 2.4 素材挂载组件

```
实现可复用组件：
1. RuinsDoor：接收 opened 布尔值，切换石门开/关两张贴图，交叉淡入淡出过渡，锚点固定不位移
2. RuinsSwitch：接收 active 布尔值，切换机关亮/灭状态贴图，附带 CSS 外发光
3. Sprite：接收 pose（idle/guide/thinking/happy）切换小精灵贴图，带悬浮上下浮动动画
4. MagicStairs：通关条件满足后淡入显示阶梯素材，隐藏时完全卸载
所有组件无业务逻辑，仅做状态到贴图的映射和基础过渡动画。
```

### 2.5 单元测试提示词

```
按 SPEC 第9节补齐测试：
1. 栈布局数学纯函数测试：入栈、出栈后每层石块坐标计算正确，空栈/单元素栈边界正确
2. AnimationStage 控制器测试：播放/暂停/步进/调速状态转换正确，不依赖 Framer Motion 真实渲染
3. StackRenderer 结构渲染测试：mock 动画库，验证给定 StructureState 时石块数量、顺序、贴图类型正确
4. App 根组件冒烟测试：应用可正常挂载无报错
```

## 三、Phase 2 Python 代码执行集成提示词

### 3.1 Pyodide Worker 执行桥

```
实现 PyodideProvider 与独立 Web Worker：Pyodide 懒加载，加载期间展示进度指示器；设置执行超时、单步指令上限，捕获无限循环/死递归，触发保护后安全终止 Worker 并重启新 Worker，页面无需刷新。exec-bridge 逻辑抽离纯模块，可在 Node 环境直接测试：捕获 stdout/stderr、将 Python 异常映射为面向 8–14 岁学生的中文友好提示（语法错误、索引越界、类型错误、空栈弹出等常见场景），不暴露原始堆栈。
```

### 3.2 代码编辑器面板

```
基于 CodeMirror 6 实现 CodeEditorPanel，提供运行、重置按钮，预置 MyStack 类骨架，学生仅填写 push/pop/peek 方法逻辑；编辑器内置栈操作语法高亮、自动缩进、基础错误行提示。运行后执行结果同步回传到 Phase 1 同一套 StackRenderer，保证实机代码驱动的可视化与脚本演示的动画表现完全一致（FR-4 要求）。
```

### 3.3 栈练习框架

```
定义 MyStack 学生代码规范，执行过程中实时采集每次 push/pop 操作，回溯生成与演示格式一致的 StructureState 动画序列；学生代码修改栈元素后，渲染器自动更新贴图类型和位置。错误状态下切换小精灵为 thinking 姿态，弹出错误提示面板，不中断页面运行。
```

### 3.4 路径回溯地图框架

```
实现岔路探索关卡舞台：背景使用地图底板素材；节点和连接线全部由 SVG 动态绘制，禁止把路线烘焙进背景图。定义节点类型（entrance/hall/corridor/deadEnd/exit），节点贴图复用资源索引；支持：已访问节点浅色填充、当前节点青蓝色描边发光、当前路径发光连线、角色沿连线平滑移动。实现路径回溯逻辑：访问死路时将节点压入路径栈，回退时依次 pop 节点并反向移动角色，栈内节点复用对应地图小图标展示。
```

### 3.5 测试要求

```
exec-bridge 纯逻辑在 Node 环境测试：stdout 捕获、异常中文映射、循环保护触发、超时判定；Worker 重启逻辑使用 mock Worker 独立单测；地图节点布局、栈回溯状态转换纯函数测试覆盖边界场景。
```

## 四、关卡内容与教学交互提示词

### 4.1 石块试炼（LIFO 认知）

```
实现第一关石块试炼：初始展示叠放石块，通过演示动画让学生观察后放入先出、最后放入先出的规律；小精灵 guide 姿态讲解后进先出概念，面板展示对应文字说明；无需代码编辑，仅做认知演示，通关后切换 happy 姿态触发星光特效。
```

### 4.2 修复阶梯（push/pop 实操）

```
实现第二关修复阶梯：给定目标栈图案顺序，学生通过调用 push() 放入指定图案石块、pop() 移除栈顶错误石块，完成目标栈状态；判定通过后石门开启、魔法阶梯淡入，小精灵沿阶梯逐级向上跳（位置补间动画，不制作逐帧精灵动画），机关切换为激活发光状态。
```

### 4.3 岔路探索（栈回溯）

```
实现第三关岔路探索：地图随机生成分叉路径，角色进入分支，遇到死路自动将路径节点压入栈，回溯时 pop 栈顶节点回退到上一个岔路；全程展示右侧路径栈面板，可视化当前栈内房间图标；到达出口节点后触发通关奖励。
```

## 六、素材批量生成提示词（分批执行）

### 第一批（Phase 1 必备）

```
先使用统一风格提示词生成 ruins-style-reference.webp 作为风格参考；后续所有素材以该图作为图生图参考，风格权重 0.8。按清单依次生成：大厅背景、关闭/开启石门、基座/月纹/日纹/星纹/裂纹石块、待机小精灵、未激活/已激活机关、魔法阶梯。同状态变体必须基于已出定稿素材编辑，保持尺寸、锚点、光照完全对齐；精灵类输出真实透明 PNG，石块统一 512×256，小精灵统一 512×512，机关统一 256×256。
```

### 第二批（Phase 2 必备）

```
基于已定稿待机小精灵生成 guide/thinking/happy 三个姿态，保持身体中心、比例、配色一致；生成地图底板和 5 个地图节点图标，节点统一 256×256，石质底板外观完全一致，仅中央图案不同。
```

### 第三批（Phase 3 美化，非阻塞）

```
生成通关徽章、魔法代码书、任务卷轴图标，以及光晕、星光、落地尘雾特效贴图；特效素材必须真实透明通道，边缘自然衰减，可叠加在场景之上不遮挡下层物体。
```
